How I work with AI on a coding project

The workflow

I've created the following visualisation to explain the scope and depth I go into in my usual workflow with AI for coding, which is making use of the superpowers plugin, and it's workflow which is an in-depth brainstorming session, followed by writing a spec and implementation plan which is then implemented automatically by using subagents to perform focused implementation tasks, followed by code review and scope/spec review gates, and follow-up fixes before proceeding to the next task.

The project

I'm currently working on a retro-themed social media project, kind of a mix of MySpace and LiveJournal and others, with thematic "day" and "night" sides to the user-facing website. The project is made up of 3 separate repositories:

Frontend

Which is a Next.js/React application, using Next.js for server-side rendering rather than a traditional SPA.

API

Which is a Spring Boot java app using jOOQ and Flyway.

Scratchpad

Which holds cross-cutting documentation only including a "roadmap" which is a glorified to-do list of the features I plan to implement.

How the projects guide the agent

The two "real" projects have their own markdown documentation explaining their architecture, testing strategy and other information that supplies the AI agent with how I want components and classes to be built and test-driven (though superpowers itself describes test-driven development too) such that I don't need to hand-hold it to do this in the way that I want it to. An effective way of working with AI is to evolve these documents over time based on the results of prior sessions.

The image-upload foundation

Prior to the session I'm about to run through, I had implemented an image upload endpoint on the API which accepts images, resizes them, and sends them to be checked by third parties for abusive or illegal content before they are approved and made available to end users, which is done by hosting them in Bunny storage (similar to Amazon S3) which is itself behind a CDN provided by Bunny. The API also produces an extremely low resolution thumbnail or hash of the image which can be used as a placeholder before it loads fully on the client, like that provided by https://blurha.sh

What this session covers

My goal for this session is to design and implement an image upload component which resizes the image in the browser before uploading it to the API and provide useful progress and feedback/error messages in such a way that I can reuse throughout the frontend, though for now only a user's profile page is implemented as a place we can make use of this component. I go into the details of how I want to achieve this, which ends up including API changes though I usually aim to only work in one project at a time, though I initially have to give very little information because the codebase and living documentation provides enough context for the agent to understand what it is I am trying to achieve. The result of this is a spec and implementation plan which you can view separately, and I can trust the agent to work through autonomously, requiring no further input from me which frees me up to do other things.
